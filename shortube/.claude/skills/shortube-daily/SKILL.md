# shortube 일일 쇼츠 브리프

인자: 오늘 만들 영상 수 (1 또는 2, 기본 1). 예: `/shortube-daily 2`

**사용자에게 주제를 묻지 말고 끝까지 진행한다.** 규칙상 진행이 불가능할 때만(후보 0개 등) 이유를 알리고 멈춘다.
모든 판단은 `COMPLIANCE_GUIDE.md`가 최우선이다. 업로드는 하지 않는다(사람이 함).
영상 제작 · 음악 · 업로드까지 이어서 요청받으면 `shortube/CLAUDE.md`(제작 · 업로드 체크리스트)를 따른다.

실행 파이썬: `.venv/Scripts/python.exe -m shortube` (Windows 콘솔 깨짐 방지로 `PYTHONIOENCODING=utf-8`).

## 1. 데이터 갱신 (매일 1회, 캐시되므로 재실행 무해)

```bash
export PYTHONIOENCODING=utf-8
.venv/Scripts/python.exe -m shortube entities       # 최근 14일 OTT 작품
.venv/Scripts/python.exe -m shortube autocomplete   # 자동완성 후보 + 필터
```
실패해도 기존 DB 후보로 계속 진행한다.

## 2. 주제 선정 (코드가 로테이션, Claude가 최종 검수)

```bash
.venv/Scripts/python.exe -m shortube pick --count <N> --json
```
슬롯마다 `category`, `entity`, `shortlist`가 나온다. 카테고리는 이미 로테이션 규칙(가중치, 연속 2회 제한, 차트 주 2회, 쿨다운)으로 정해졌으니 **바꾸지 않는다.**

shortlist를 위에서부터 보고 아래에 해당하면 건너뛰어 **첫 번째로 통과한 것**을 고른다:
- 실존 인물(연예인·유튜버·강사 등) 이름이 들어 있음 → 제외
- 채널명·특정 영상 제목으로 보이는 것 → 제외
- 너무 포괄적이라 한 영상 주제가 안 됨("소름돋는 사실들") → 제외
- 지난 시점 수치(예: 오늘이 10월인데 "순위 9월")는 차트형이면 최신 시점으로 바꿔 다룬다; 불가능하면 제외
- 의료·투자·법률 조언으로 흐를 주제 → 제외 (단순 원리 설명은 가능, 치료·복용 권유 금지)
- 공인 출처 2개 이상을 찾을 수 없을 것 같은 주제 → 제외

shortlist가 모두 탈락하면 `pick`의 다른 후보를 보기 위해 해당 키워드를 건너뛸 수 없으니, 그 슬롯은 같은 카테고리 안에서 shortlist 주제를 **구체화**(예: "몰랐던 사실" → 공공 출처가 있는 구체 현상)해 진행하고 브리프에 그 사실을 적는다.

explain 슬롯은 shortlist 전체(같은 작품의 원작/몇 부작/공개일/촬영지 등)를 **한 영상에 묶는다.** 대표 키워드는 검색 수요가 가장 클 것 같은 의도 하나로 정한다.

## 3. 카테고리별 제작 흐름

공통 규칙 (COMPLIANCE_GUIDE 4장):
- 출처 조사: WebSearch/WebFetch. 등급 A(공공·정부·공식 발표) > B(위키백과) > C(언론·공식 사이트, 사실만). `config/sources.yaml`의 `blocked_domains`(나무위키, 커뮤니티 등)는 열지도 말 것.
- 사실 카드: 원문 문장을 옮기지 말고 원자적 사실 1개 = 내 말 1문장. 사실마다 독립 출처 2개 또는 1차 출처 1개. 수치·날짜는 출처 원문에서 다시 확인. 출처끼리 다르면 대본에서 빼거나 "기관마다 다르다"로 표현.
- 대본은 사실 카드만 보고 쓴다. 출처 문장과 같은 표현(연속 20자 이상)이 없게 한다.
- 부가가치 요소 1개 이상 필수: 직접 계산·비교, 여러 출처 종합, 시계열 해석, 오해 바로잡기 중 하나.
- 화면: 텍스트(키네틱 타이포), 직접 그릴 차트, 타임라인, 라이선스 명확한 아이콘만. 포스터·스틸컷·인물 사진·로고·스크린샷 금지.

### explain — 신작 드라마/영화 정보형
1. 공식 출처 먼저: 플랫폼 공식(넷플릭스 about/tudum, 티빙·디즈니+ 보도자료), 원작 플랫폼 작품 페이지(웹툰·소설), 위키백과, 언론 기사(사실만).
2. 담을 사실: 공개일·공개 방식(일괄/주간), 회차 수, 원작 여부와 원작 정보, 촬영지(공식 확인된 것만), 장르. 줄거리는 공식 시놉시스 수준을 **내 말로 1~2문장**만.
3. 금지: 결말·반전 서술, 배우 사생활·외모·평가, 회차별 상세 줄거리. 출연진은 이름 1줄까지.
4. 부가가치 예: "원작 웹툰 대비 회차 압축", "같은 플랫폼 최근 신작들과 회차·공개 방식 비교".

### trivia — 상식/잡학형
1. 출처: 공공기관(국가건강정보포털, 기상청, 국립국어원 등), 백과, 학술·교육 기관.
2. 구조: 질문 훅 → 원리 2~3단계 → 흔한 오해 1개 바로잡기 → 한 문장 정리.
3. 건강 관련이면 "원리 설명"까지만, 치료·복용 권유 금지, "증상이 지속되면 전문가 상담" 1줄.

### chart — 차트/순위형
1. 출처: 공식 차트 사이트(넷플릭스 Top 10, 영화진흥위원회 KOBIS 등). 시점(`as_of`)을 반드시 확인.
2. 상위 3~10개만 인용. 표 전체를 옮기지 않는다.
3. 부가가치: 지난 주 대비 변동, 누적 주수, 장르 분포 등 직접 분석. 화면은 직접 그린 순위 막대/변동 차트.
4. 로고·포스터 금지, 출처는 텍스트로.

## 4. 브리프 작성

파일: `output/briefs/YYYY-MM-DD_slot<N>.md` (폴더 없으면 생성). 아래 템플릿을 채운다.

```markdown
# [카테고리] 제목 가안
- 날짜 / 슬롯 / 대표 키워드 / 작품(있으면)
- 선정 근거: 로테이션 결과 + shortlist에서 고른 이유 (건너뛴 후보와 사유)

## 출처
| # | 기관/사이트 | 문서 | URL | 등급 | 확인일 |

## 사실 카드
(yaml: id, claim(내 말), value, as_of, sources[#], verified)

## 대본 (30~60초)
| 시간 | 내레이션 | 화면 텍스트/그래픽 |
| 0~3s | 훅 (실제 내용에 있는 것만) | ... |
...
- 부가가치 요소: (무엇을 더했는지 한 줄)

## 화면 구성
- 사용 요소: 타이포/차트(데이터: 사실 카드 id)/타임라인/아이콘(라이선스)
- 사용 금지 요소 없음 확인

## 메타데이터
- 제목 후보 3개 (내용과 일치, 자극 단어는 내용에 있을 때만)
- 설명란 (출처 목록 + "OO년 O월 기준" + AI 사용 고지 1줄)
- 태그 ≤ 10

## 검수 체크리스트 (COMPLIANCE_GUIDE 4-9)
- [x]/[ ] 항목별로 Claude 자체 점검 결과. 사람이 확인해야 할 항목은 [ ]로 남기고 이유를 적는다.
```

## 5. 이력 기록

브리프 저장 후 슬롯마다:
```bash
.venv/Scripts/python.exe -m shortube log-topic "<대표 키워드>" --category <cat> [--entity "<작품>"] [--intent "<의도>"] --brief output/briefs/<파일>.md
```
기록해야 다음 날 로테이션·쿨다운에 반영된다.

## 6. 사용자에게 보고

슬롯별 3~4줄: 카테고리, 주제, 핵심 사실 2개, 브리프 경로, 사람이 확인할 항목. 브리프 전문을 채팅에 붙이지 않는다.
