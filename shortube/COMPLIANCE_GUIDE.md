## 0. 핵심 원칙 5줄 요약

1. **사실은 가져오고 표현은 직접 만든다.** 사실·수치는 저작권 보호 대상이 아니지만, 기사·블로그의 문장·구성·사진은 보호된다.
2. **사람(개인)에 대한 콘텐츠는 만들지 않는다.** 한국은 *사실을 말해도* 명예훼손이 성립할 수 있다(형법 307조 1항). 연예인 근황·논란은 범위에서 뺀다.
3. **이미지·영상·음원은 외부에서 가져오지 않는다.** 화면은 텍스트, 직접 그린 차트, 라이선스가 명확한 아이콘/지도만 쓴다.
4. **영상마다 "내가 더한 가치"가 있어야 한다.** 같은 틀에 단어만 바꾼 대량 생산은 YouTube 수익화 정책상 "inauthentic content"로 수익 창출 대상에서 빠진다.
5. **자동화는 "초안까지", 게시는 사람이.** 수집→초안→검수 대기열까지만 자동화하고, 공개 버튼은 사람이 누른다.

## 1. 리스크 판정표

### 1-1. 금지 (만들지 않음)

| 항목 | 이유 |
|---|---|
| 연예인·유명인 **근황, 열애, 결혼, 이혼, 사망, 논란, 폭로, 의혹** 콘텐츠 | 사실적시 명예훼손(형법 307①, 정보통신망법 70조), 사생활 침해. "공식 보도 확인"만으로는 면책되지 않음 |
| 인물 사진, 포스터, 스틸컷, 앨범 아트, 방송 캡처, 뉴스 화면 캡처 | 저작권 + 초상권 |
| 기업·서비스 **로고**(넷플릭스, 멜론, 빌보드 등) | 상표·오인 유발. 출처는 **텍스트로만** 표기 |
| 기사·블로그·나무위키 문장 복사 또는 "살짝 바꿔쓰기" | 저작권 침해(2차적 저작물), 나무위키는 CC BY-NC-SA라 수익 채널 사용 불가 |
| 차트 **전체**(TOP 100 등)를 매주 그대로 옮기기 | 데이터베이스 제작자 권리(저작권법 93조) — 상당 부분 반복 복제 위험 |
| 유명인 목소리 복제 TTS, 실존 인물 발언처럼 보이는 합성 | 퍼블리시티권(부정경쟁방지법 2조1호 타목), YouTube 합성 콘텐츠 정책 |
| 상업 음원, 다른 채널 BGM | Content ID 클레임/저작권 경고 |
| 드라마·영화 **결말 상세 재서술**(장면 순서대로 요약) | 줄거리의 상세 재현은 2차적 저작물 리스크 + 스포일러 반감 |
| 조회수·구독·댓글 자동화 봇, 다계정 운영 | YouTube 스팸 정책 직접 위반 |
| 내용과 무관한 자극 제목·썸네일 문구(충격, 실화 등을 내용 없이) | YouTube "오해의 소지가 있는 메타데이터" 스팸 정책 |
| 태그·설명란 키워드 나열 | YouTube 키워드 스터핑 금지 |

### 1-2. 조건부 허용 (안전장치 필수)

| 항목 | 조건 |
|---|---|
| 차트/순위형 | 상위 **3~10개만** 인용 + 출처 텍스트 + 날짜. 순위표를 그대로 옮기지 말고 *변동·비교·맥락*을 본인 분석으로 덧붙인다 |
| 작품(영화·드라마) 정보형 | **공개된 사실**(공개일, 회차 수, 원작 여부, 흥행 수치)만. 줄거리는 공식 시놉시스 수준 1~2문장을 직접 표현으로 |
| 인물 "필모그래피/대표작" | **작품 목록이라는 공개 사실만**, 평가·사생활·외모 언급 금지, 얼굴 이미지 금지. 이름을 제목 미끼로 쓰지 않는다. 가능하면 1차에서는 이 카테고리 자체를 보류 |
| AI(LLM)로 대본 초안 작성 | 사실 카드(4-3)만 입력으로 쓰고, 사람이 검수·수정. 원문 유사도 검사(4-5) 통과 필수 |
| TTS 내레이션 | 상업 이용 허용 라이선스의 TTS만, 실존 인물 목소리 모사 금지. 가능하면 본인 목소리 |
| YouTube API로 업로드 | `privacyStatus=private`로만 올리고 공개 전환은 사람이 수동으로 (5장) |

### 1-3. 안전 (권장 카테고리)

- **상식/잡학형**: 과학·언어·역사·생활 상식. 출처가 공공·교과·백과 수준으로 풍부하고 인물 리스크가 없다.
- **오늘의 역사**: 50년 이상 지난 공적 사건 위주(생존 사인(私人) 언급 금지).
- **공공 통계 해설**: KOSIS·공공데이터포털 수치를 직접 차트로 그려 해설. 이미지 없이도 시각 자료가 생긴다.
- **"~하는 이유" 설명형**: 제도·현상·단어 유래 등.

## 3. 주제 탐색 자동화 (SPEC 보완)

### 3-1. 원칙
- **공식 API 우선, 비공식 엔드포인트는 보조.** 비공식 소스(자동완성, pytrends)는 낮은 빈도·대기 시간 준수, 실패해도 파이프라인이 멈추지 않게.
- 수요 신호만 보지 말고 **"만들 수 있는가"(출처·리스크)를 같이 본다.** 수요 높고 출처 없는 주제보다 수요 중간·출처 탄탄한 주제가 낫다.

### 3-2. 추가할 수요 신호 소스 (모두 무료·공식)

| 소스 | 용도 | 비고 |
|---|---|---|
| Wikimedia REST API — 문서 조회수 (`/metrics/pageviews/per-article/ko.wikipedia/...`) | 한국어 위키 문서별 일간 조회수 → 관심도·급상승 | 키 불필요, User-Agent에 연락처 명시 권장. 절대 수치라 정규화 문제 없음 |
| Wikimedia "많이 본 문서" (`/metrics/pageviews/top/ko.wikipedia/...`) | 그날 관심 주제 발굴 | 인물 문서는 자동 제외 필터(분류 정보 또는 `entity_type` 판정) |
| 위키백과 "오늘의 역사"용 날짜 문서 | trivia/오늘의 역사 후보 | 텍스트는 CC BY-SA → 문장 복사 금지, 사실만 추출 |
| 공공데이터포털(data.go.kr), KOSIS OpenAPI | 통계형 주제 후보 + 차트 데이터 | 공공누리 1유형/이용허락 범위 확인 후 사용 |
| 네이버 DataLab, YouTube Data API, 자동완성 | SPEC 기존 | 그대로 |

### 3-3. 출처 확보 가능성 점수 (`source_availability`, 0~100)

키워드마다 자동으로 다음을 확인한다.

1. 한국어 위키백과에 해당 주제 문서가 있는가 (+30)
2. 공공·공식 출처(정부, 공공기관, 학회, 기업 공식 발표, 공식 차트 사이트)에서 1건 이상 확인되는가 (+40)
3. 서로 독립적인 출처가 2개 이상인가 (+30)

- 60 미만이면 리포트에 "출처 부족 — 제작 보류" 표시.
- 수집은 **검색 결과 URL과 제목만** 저장하고 본문은 이 단계에서 저장하지 않는다(본문 수집은 4장 제작 단계에서 필요한 것만).

### 3-4. 주제 적합성 필터 (자동)
- `entity_type=person` → 제외
- 리스크 사전 매칭 → 제외
- 미성년자, 사고·재난 피해자, 범죄 사건의 피해자/피의자 관련 → 제외
- 의료·투자·법률 조언형("~하면 낫는다", "~사면 오른다") → 제외 (YouTube 의료 허위정보 정책, 투자 권유 리스크)

### 3-5. 출력 추가
`output/topics_shortlist.csv`: keyword, category, score, source_availability, 추천 출처 URL 3개, 제외 사유(있으면)

## 4. 콘텐츠 제작 방법론 — 인터넷 정보 취합 → 직접 생성 (이미지 생성 없음)

### 4-1. 파이프라인 전체 흐름

```
[주제 확정] → (1) 출처 수집 → (2) 사실 카드 추출 → (3) 교차 검증
          → (4) 대본 작성(사실 카드만 입력) → (5) 원문 유사도 검사
          → (6) 화면 구성(텍스트·차트) → (7) 오디오 → (8) 메타데이터·출처 표기
          → (9) 사람 검수 체크리스트 → (10) 비공개 업로드 → 사람이 공개
```

> 2026-10-22 사용자 결정: Studio(브라우저) 업로드는 (10)을 건너뛰고 바로 **공개**로 게시한다 (CLAUDE.md 5장). API 업로드의 `private` 제한(아래 표)은 그대로다.

각 단계 결과는 SQLite에 저장하고, 단계별 독립 실행·재개 가능(SPEC 2장 원칙 동일).

### 4-2. (1) 출처 수집 — 라이선스 등급

| 등급 | 예시 | 사용 방법 |
|---|---|---|
| **A: 자유 이용** | 공공누리 1유형, 정부 보도자료, 공공데이터, 퍼블릭 도메인, CC0 | 사실·수치 추출 자유, 출처 표기 |
| **B: 출처 표기 조건** | CC BY, CC BY-SA(위키백과) | 사실만 추출. 문장 인용 시 라이선스 의무 발생 → 문장은 쓰지 않는다 |
| **C: 사실만 참고** | 언론 기사, 공식 차트 사이트, 기업 홈페이지 | 사실·수치만 추출, 문장·구성·이미지 사용 금지, 출처 텍스트 표기 |
| **D: 사용 금지** | 나무위키(CC BY-NC-SA), 유료 기사, 커뮤니티 글, 타 유튜버 영상/대본, 출처 불명 블로그 | 수집 대상에서 제외 (도메인 블랙리스트) |

수집 규칙:
- `robots.txt` 준수, 도메인당 요청 간 최소 2초, User-Agent 명시, 로그인 필요한 페이지 접근 금지.
- 원문 HTML은 **검증용 임시 캐시**로만 보관(기본 30일 후 삭제), 재배포·공개 금지.
- 각 문서에 `url, domain, license_tier, fetched_at, title` 기록.

### 4-3. (2) 사실 카드 (fact card) — 핵심 데이터 단위

원문 문장을 대본으로 옮기지 않기 위해, **원문 → 사실 카드 → 대본**의 단방향 흐름을 강제한다. 대본 작성 단계는 원문을 보지 못하고 사실 카드만 본다.

```yaml
- id: F0012
  topic: "왜 바나나는 휘어 있을까"
  claim: "바나나는 자라면서 햇빛 쪽으로 끝이 위로 휘는 굴광성을 보인다"   # 내 말로 1문장
  value: null              # 수치형이면 숫자 + unit
  as_of: null              # 시점이 중요한 사실이면 날짜
  sources:
    - url: https://...
      license_tier: A
      evidence: "원문 근거 위치(문단 번호 등) — 문장 복사 저장 금지, 최대 짧은 구절"
    - url: https://...
      license_tier: C
  verified: true           # (3) 통과 여부
  sensitivity: none        # none | person | health | finance → none 외에는 검수 강화
```

추출 방법:
- LLM을 쓸 경우 프롬프트에 "원문 문장을 그대로 쓰지 말고, 원자적 사실 1개당 1문장으로 재진술"을 명시하고 출력은 위 스키마(JSON)로 강제.
- 숫자·날짜·고유명사는 원문에서 **정규식으로 재확인**(LLM 환각 방지).

### 4-4. (3) 교차 검증
- 사실 카드 1개당 **독립 출처 2개 이상**, 또는 **1차 출처(공식 기관·당사자 발표) 1개**.
- 출처끼리 수치가 다르면 `conflict=true` → 대본에서 제외하거나 "기관마다 차이가 있다"로 표현.
- 시점 민감 사실(순위, 통계)은 `as_of` 필수, 화면에 "OO년 O월 기준" 표기.
- 검증 실패 카드는 대본 입력에서 자동 제외.

### 4-5. (4)·(5) 대본 작성과 원문 유사도 검사

**대본 구조(쇼츠 30~60초)** — 템플릿은 3~5종을 돌려 쓰고, 영상마다 구성을 다르게 한다(대량생산 판정 회피).
1. 훅(0~3초): 질문 또는 의외의 사실 1개 — *내용에 실제로 나오는 것*만
2. 본문: 사실 카드 3~6개를 **내 관점의 흐름**으로 엮기(비교, 순서, 원인→결과)
3. **부가가치 요소 1개 이상 필수**: 직접 계산(환산·비교), 여러 출처 종합 순위, 시계열 변화 해석, 오해 바로잡기 중 하나
4. 마무리: 출처 안내("자료 출처는 설명란") + 다음 영상 연결

**원문 유사도 검사(자동, 통과 못 하면 검수 대기열로 못 감)**
- 대본과 수집 원문 각각을 문자 단위 5-gram으로 나눠 겹침 비율 계산 → **어느 한 출처와도 15% 초과 시 실패**.
- 원문과 **연속 20자 이상 동일** 구간이 있으면 실패.
- 고유명사·숫자는 겹쳐도 되므로 검사 전 마스킹.
- 결과를 `script_checks(script_id, max_overlap, longest_match, passed)`에 저장.

### 4-6. (6) 화면 구성 — 이미지 없이 만드는 방법

### 4-7. (7) 오디오
- 내레이션: 본인 녹음 우선. TTS는 상업 이용 허용 약관 확인 후 사용, 약관 사본·사용 날짜 기록.
- BGM/효과음: **YouTube 오디오 보관함**의 저작자 표시 불필요 트랙 위주. 트랙 ID를 영상 메타데이터에 기록.
- 자막: 대본에서 자동 생성(번인 자막 + 업로드 자막 파일).

### 4-8. (8) 메타데이터·출처 표기
- 설명란 템플릿:
  ```
  [자료 출처]
  - 기관/사이트명, 문서 제목, URL (확인일 YYYY-MM-DD)
  - ...
  ※ OO년 O월 기준 정보이며 이후 바뀔 수 있습니다.
  [음악] YouTube 오디오 보관함 - 트랙명
  ```
- CC BY / CC BY-SA 자료에서 *수치·사실만* 가져왔어도 출처는 표기한다(신뢰도 + 분쟁 예방).
- 제목·태그는 내용에 실제로 있는 단어만. 태그는 10개 이하.
- **AI 사용 표시**: 대본 초안·TTS에 AI를 썼다면 설명란에 "대본 초안 작성 및 내레이션에 AI 도구를 사용했으며 사람이 검수했습니다" 1줄. YouTube 업로드 화면의 "변경되거나 합성된 콘텐츠" 항목은 *실제처럼 보이는 사람·사건·장소를 합성*한 경우 "예" — 이 방식(텍스트·차트)에서는 보통 해당 없음이지만, 실존 인물 목소리처럼 들리는 TTS를 쓰면 반드시 "예". 한국 AI 기본법(2026-01 시행)의 표시 의무는 주로 AI 사업자 대상이지만 자발적 표시를 기본값으로 한다.

### 4-9. (9) 사람 검수 체크리스트 (영상 1개당, 전부 체크해야 공개)

- [ ] 실존 개인(공인 포함)에 대한 평가·사생활 언급이 없다
- [ ] 화면에 외부 이미지·로고·캡처가 없다
- [ ] 모든 사실 카드가 검증 통과(verified=true)이고 시점 표기가 있다
- [ ] 원문 유사도 검사 통과
- [ ] 이 영상만의 부가가치 요소가 무엇인지 한 문장으로 말할 수 있다
- [ ] 제목·첫 3초 훅이 실제 내용과 일치한다
- [ ] 설명란 출처·음악·AI 사용 표기 완료
- [ ] 의료·투자·법률 조언으로 읽힐 문장이 없다
- [ ] 최근 업로드 5개와 구성·문장 패턴이 지나치게 같지 않다

검수 결과는 `reviews(video_id, reviewer, checked_items, approved_at)`로 남긴다(분쟁 시 주의 의무 이행 근거).

## 8. 자주 생기는 회색지대 판단 기준

- **"넷플릭스 순위 TOP 10" 영상** → 공식 Top 10 사이트에서 순위 *사실*만 가져와 상위 몇 개 + 변동 분석 + 출처 표기. 포스터·로고·예고편 없이 타이포와 순위 차트로 구성. OK.
- **"OO 드라마 몇 부작/원작"** → 공개 사실, 짧게. OK. 결말·반전 서술은 X.
- **"배우 OO 대표작"** → 1차에서는 보류. 하게 되더라도 작품 목록만, 얼굴·평가 X.
- **"오늘의 역사"** → 공적 사건, 위키 문장 복사 X, 2개 출처 교차 확인. OK.
- **"OO 하는 이유"(과학·생활)** → 가장 안전. 1차 메인 카테고리로 권장.
- **다른 쇼츠가 터진 주제를 같은 주제로 제작** → 주제는 보호 대상이 아니므로 OK. 단 그 영상의 대본·구성 순서·제목 문구를 따라 하지 않는다(경쟁 쇼츠는 *패턴 통계*로만 참고).
