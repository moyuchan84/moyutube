# 모라구 카테고리 — 눈으로 보는 수학·과학 (작업명)

별도 채널을 만들지 않고, **모라구 채널 안의 카테고리(재생목록)** 로 운영한다. 채널이 갈라지면 구독자가 분산되기 때문이다.

- 폴더: `lab/` (작업 폴더일 뿐, 채널 이름이 아니다)
- 모라구 안에서의 위치: 가족 대화(qna) · 동화(fairy) 옆의 **설명 영상 카테고리**. 제목 앞머리 말머리 예: `[눈으로 보는 수학]`, 재생목록 하나로 묶는다.
- 한 줄 컨셉: **"말로 들으면 어려운데, 움직이는 걸 보면 아~ 하는 순간"**
- 시청 대상: 초등 3~6학년 + 같이 보는 부모. 설명 그림이 주인공이다.
- 채널 이름 · 배너 · 프로필은 새로 만들지 않는다 (모라구 것을 그대로 쓴다). 카테고리용 썸네일 틀(색 · 말머리)만 따로 정한다.

## 1. 다른 갈래와의 차이

| | qna | fairy | **lab** |
|---|---|---|---|
| 화면 | AI 그림 + 대화 | 동화책 그림 | **코드로 그리는 도형 · 그래프 · 식** |
| 음성 | 부모/아이 | 동화 낭독 | 해설 한 명 (차분한 선생님 톤) |
| 강점 | 공감 | 감성 | **정확한 수식 · 도형 변환 · 반복 가능** |

코드로 그리기 때문에 **AI 그림처럼 손이 틀어지거나 글자가 깨지는 문제가 없고**, 숫자·수식이 정확하다. 이게 이 갈래를 따로 둘 이유다.

## 2. 도구 — Manim vs Motion Canvas (이 저장소 기준 추천)

자세한 비교는 [TOOLS.md](TOOLS.md). 요약:

| | Manim (Python) | Motion Canvas (TypeScript) | Remotion (이미 사용 중) |
|---|---|---|---|
| 잘하는 것 | 수식(LaTeX) · 도형 변환 · 그래프 | 코드로 애니메이션 + 편집기에서 타이밍 조절 | 한글 자막 · 레이아웃 · 음성 동기 |
| 설치 부담 | 큼 (Python + LaTeX + ffmpeg + Cairo) | 작음 (npm) | 이미 있음 |
| 수학 식 | ◎ 기본 제공 | △ LaTeX 지원 있으나 덜 매끈 | △ KaTeX 직접 연결 |
| 이 PC 현재 | Python **없음**, ffmpeg **없음** | node 24 있음 | 있음 |

**추천: Motion Canvas 로 시작 → 식이 많이 필요한 편만 Manim.**
이유: 이 PC 에는 Node 만 있고 Python · ffmpeg 가 없다. 도형 · 그래프 위주의 초등 수준 수학 · 과학은 Motion Canvas 로 충분하다. 한글 자막과 음성은 기존 파이프라인(Remotion + Gemini TTS)이 이미 있으니, 설명 장면만 Motion Canvas 로 렌더해 Remotion 에서 합치는 방식도 가능하다. 먼저 **시험 1편(아래 후보 1번)을 Motion Canvas 로 만들어 보고** 판단한다.

## 3. 에피소드 형식 (롱폼 3~5분 · 쇼츠 30~45초)

1. **질문** (10초) — "공은 왜 둥글까?" 한 문장, 화면에 큰 글자
2. **눈으로 보기** — 도형 · 그래프가 움직이며 답을 보여 줌 (이 갈래의 핵심)
3. **한 번 더, 쉽게** — 일상 비유 한 개 (피자, 계단, 그네…)
4. **직접 해보기** — 집에서 종이 · 물 · 컵으로 할 수 있는 실험 (안전한 것만)
5. **한 문장 정리**

규칙: 한 편에 **개념은 하나만**. 식은 한 화면에 하나. 외우게 하지 말고 "왜"를 보여 준다.

## 5. 제작 절차 (초안)

1. 주제 한 개 → 질문 · 정답 · 비유 · 실험 한 줄씩 정리 (`episodes/NN-slug/brief.md`)
2. 해설 대본 작성 → 장면별 시간 배분
3. 장면 코드 작성 (Motion Canvas `scenes/` ) → 미리보기로 타이밍 확인
4. 음성: Gemini TTS (루트 `.env` 키, **요청할 때만 실행** — 비용 발생)
5. 한글 자막 · 합성은 Remotion, 또는 Motion Canvas 단독 렌더
6. 업로드 기본 **비공개** → 저장 후 실제 공개 상태 재확인

## 6. 시험작 결과 (2026-10-22) — 원 시리즈 2편

두 편은 이어서 본다: **1편이 "둘레 = 2πr"을 만들고, 2편이 그 식을 이어받아 "넓이 = πr×r"을 만든다.**

| 편 | 질문 | 핵심 장면 | 파일 | 길이 |
|---|---|---|---|---|
| 1편 | 원의 둘레는 왜 2×π×r? | 원을 한 바퀴 굴려 둘레 길이를 얻고, 지름으로 재면 "3개 + 조금"(=π) | `src/scenes/circleLength.tsx` → `output/circleLength.mp4` | 39초 |
| 2편 | 원의 넓이는 왜 π×r×r? | 원을 잘라 엇갈려 붙이면 직사각형 (가로 πr, 세로 r) | `src/scenes/circleArea.tsx` → `output/circleArea.mp4` | 27초 |

- 연결: 1편 끝에 "다음 편: 원의 넓이는 왜 π×r×r?", 2편 시작에 "지난 편에서 알아낸 것: 원둘레 = 2×π×r" 를 넣었다.
- 둘 다 1080×1920 · 30fps · 음성/자막/배경음악 없음 (시험작).
- Motion Canvas 로 **설치 · 장면 코드 · mp4 렌더까지 Node 만으로 된다** (Python · LaTeX 불필요). 영상 출력은 번들된 ffmpeg 가 처리한다.
- 실행: `cd lab && npm install && npx vite` → 브라우저에서 프로젝트 선택(circleLength / circleArea) → 왼쪽 Video Settings 아래 RENDER (exporter: Video (FFmpeg)). 결과는 `lab/output/`.
- 1편 한계: π 를 "측정으로 3.14… 쯤"이라고 보여 주는 설명이다 (증명이 아니라 정의에 가까움). 초등 수준에서는 이게 맞는 설명이다. 지름 3개 뒤의 "조금" 막대가 작아서 잘 안 보인다 → 확대 장면 추가 개선안.
- 2편: 위아래 가장자리의 톱니(호 모양)는 조각 수를 늘려도 남는다 — "거의 직사각형"이라고 말하는 근거로 둔다.

### 디자인 (2026-10-22 개편)

- 공통 스타일은 `src/style.tsx` 하나에 모았다. 새 편도 이것을 가져다 쓴다: `Backdrop`(남색 방사형 배경 + 옅은 모눈), `addChrome`(말머리 · 제목 · 자막 카드), `rise`(떠오르기), `swapTex`(수식 바꾸기).
- 색: 배경 남색 `#0E1326`, 글자 `#F4F1EA`, 강조 앰버 `#FFC24B` · 민트 `#3DDBC4` · 라벤더 `#9B8CFF` · 코랄 `#FF7A7A`. 도형 · 선은 같은 색 그림자(shadowBlur)로 빛나게.
- 글꼴: Pretendard (`src/fonts.ts` 가 웹폰트를 받아 둔다). 수식은 `Latex`(MathJax).
- 배치: 위에서부터 말머리(-850) → 제목(-740/-630) → 도형 무대 → 수식 카드 → 자막 카드(+440). **y > 580(아래 20%)은 쇼츠 UI 가 덮으니 비운다.**
- 함정: Latex 의 `tex(...)` 자동 변형(`{{}}` 짝 맞추기)은 "Matching between Latex SVG and tex parts failed" 오류를 내고 편집기를 멈추게 했다 → 쓰지 않고 `swapTex` 로 바꾼다. `tex` 에 배열을 넘기면 `\pi` 가 글자로 찍힌다 → 문자열만 쓴다.
- 함정: 렌더 중에 장면 파일을 고치면 vite 가 다시 불러오면서 mp4 마무리가 멈춘다 → 렌더 끝날 때까지 파일을 건드리지 않는다.
- 2편 직사각형: 마지막 조각을 반으로 갈라 오른쪽 반을 맨 왼쪽에 붙여서 양끝이 수직인 정확한 직사각형이 된다 (예전의 기울어짐 해결).
