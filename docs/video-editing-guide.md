# AI 영상 편집 가이드 — 녹화 · 컷 편집 · 자막 · 효과음

2026-11-01 사용자 요청으로 정리했다. 출발점은 사용자가 본 글로, 영상 편집자가 Claude 에 편집을 맡겨 주 1회이던 업로드를 주 5회로 늘렸다는 내용이다. 그 글의 6가지 방법을 이 저장소에 맞게 고쳐 적었다.
**유튜브 영상을 편집할 때는 채널과 상관없이 이 문서를 먼저 읽는다.** 그대로 쓰는 항목과 채널에 맞게 바꾼 항목은 각 절에 적어 두었다.

| # | 원래 글의 방법 | 이 저장소에서 |
|---|---|---|
| 1 | 녹화하다 말이 꼬이면 한 템포 쉬고 다시 말한다 (무음으로 재테이크를 알아냄) | **사람이 직접 녹화 · 녹음하는 영상**에서 그대로 쓴다. AI 음성(TTS)으로 만드는 편(qna · 내모남불 · shortube · funtube)은 해당 없음 |
| 2 | 위스퍼(whisper) large-v3-turbo 설치 | 녹화 영상이 처음 들어올 때 설치한다 (아래 2절) |
| 3 | 무음 구간을 다 자르고, 같은 말을 반복했으면 앞 테이크를 지우고 뒤 테이크를 살린다 | 녹화 영상의 컷 편집 규칙 (3절). TTS 편은 지금처럼 `trim-voice` 로 앞뒤 무음만 자른다 |
| 4 | 자막은 '넷플릭스 한국어 자막 지침'을 정확히 따른다 | **모든 채널의 한국어 자막(srt)에 적용.** qna 는 `npm run motion-srt` 가 자동으로 맞춘다 (4절) |
| 5 | Remotion 대신 HyperFrames | **기존 채널은 Remotion 을 그대로 쓴다.** 새 프로젝트에서 시험해 보는 것만 검토한다 (5절) |
| 6 | Leonxlnx/earshot 으로 효과음 | 지금은 코드로 합성하는 효과음(`qna/video/scripts/sfx.mjs`)을 쓴다. earshot 도 코드로 렌더하는 방식이라 규칙과 맞다. 써 볼 때는 사용자에게 먼저 묻는다 (6절) |

## 1. 녹화할 때 — 촬영하면서 편집하기

- 말이 꼬이면 멈추지 말고 **1~2초 쉰 다음 그 문장을 처음부터 다시** 말한다. 녹화는 계속 켜 둔다.
- 쉬는 구간(무음)이 재테이크 표시가 된다. 편집할 때 "무음 앞 문장 = 버리는 테이크"로 판단한다.
- 화면 녹화나 카메라 영상을 받으면 원본은 편 폴더 밖, git 에 올리지 않는 곳에 둔다 (예: `<채널>/content/<편>/raw/`는 `.gitignore` 에 넣는다). 용량이 크기 때문이다.

## 2. 받아쓰기 — whisper large-v3-turbo

- 원래 글의 "whisper l3t" 는 **large-v3-turbo** 모델을 말한다. large-v3 를 줄인 모델이라 빠르고 메모리를 덜 쓴다. 원래 글에 따르면 기본 위스퍼를 깔면 사양이 낮은 컴퓨터는 버티지 못할 수 있다.
- 설치는 녹화 영상을 처음 편집할 때 한 번만 한다. 미리 깔아 두지 않는다. 추천 구성은 `faster-whisper` (CTranslate2), 모델 `large-v3-turbo`, CPU 는 `compute_type="int8"`, 언어는 `ko`, 단어 단위 타임스탬프는 `word_timestamps=True`.
- 파이썬 패키지는 그 채널의 `.venv` 에 설치한다 (shortube 처럼). 모델 파일은 git 에 올리지 않는다.
- 결과는 단어마다 시작 · 끝 시각이 붙은 JSON 으로 남긴다. 3절의 컷 편집과 4절의 자막이 이 JSON 을 쓴다.

## 3. 컷 편집 — 무음 자르기와 재테이크 고르기

1. **무음 구간 찾기:** ffmpeg `silencedetect` 로 찾는다 (시작값 `noise=-35dB:d=0.6`, 목소리 크기에 맞춰 조정). 말 앞뒤로는 0.1~0.15초씩 여유를 남긴다. 딱 붙여 자르면 숨소리 · 첫 자음이 잘린다.
2. **반복 찾기:** 받아쓰기 문장을 차례로 비교한다. 무음 바로 앞뒤 문장이 같은 말로 시작하거나, 글자가 70% 넘게 겹치면 재테이크로 본다. 이때 **앞 테이크를 지우고 마지막 테이크를 살린다.**
3. **사람 확인:** 자를 목록(EDL: 시작 · 끝 · 이유)을 먼저 만들어 보여 준다. 렌더는 그다음에 한다. 농담이 일부러 반복된 경우처럼, 판단이 애매한 곳은 표시만 하고 자르지 않는다.
4. 잘라 붙인 영상을 기준으로 받아쓰기 시각을 다시 계산해서 4절의 자막을 만든다.

TTS 편(qna 모답맨 · 내모남불 등)은 줄마다 음성 파일이 따로 있다. 그래서 지금 방식을 그대로 쓴다: `npm run trim-voice -- <편>` 으로 앞뒤 무음 자르기 → `voice` → `speed`.

## 4. 자막 — 넷플릭스 한국어 자막 지침 (Korean Timed Text Style Guide)

원문: https://partnerhelp.netflixstudios.com/hc/en-us/articles/216001127 (2026-11-01 확인. 숫자를 바꾸기 전에 원문을 다시 본다)

| 항목 | 규칙 |
|---|---|
| 한 줄 글자 수 | **16자.** 한글은 1자, 라틴 문자 · 공백 · 문장부호는 0.5자로 센다 |
| 줄 수 | **최대 두 줄.** 16자 안이면 한 줄로 둔다. 두 줄에 안 들어가면 자막을 둘로 나눈다 |
| 줄 나누기 | 문장부호 뒤에서 먼저 끊는다. 고를 수 있으면 **아래 줄이 더 긴 피라미드 모양**으로 한다 |
| 읽기 속도 | 성인 초당 **12자**, 어린이 초당 9자 (청각장애인용 SDH 는 14 · 11) |
| 마침표 · 쉼표 | **줄 끝에는 마침표 · 쉼표를 쓰지 않는다.** 한 자막 안에서 두 문장을 이을 때만 쉼표를 쓴다 |
| 느낌표 · 물음표 | 느낌표는 외치거나 놀랄 때만 쓴다. 둘을 같이 쓰면 `?!` 순서로 (예: 뭐?!) |
| 말줄임 | `…` 한 글자로 쓴다 (마침표 셋 금지). 2초 넘게 쉬거나 망설이거나 말이 끊길 때 쓴다. 한 문장이 다음 자막으로 이어질 때는 쓰지 않는다 |
| 따옴표 | 화면 글자 · 강조는 ' '. 화면 속 글자를 자막으로 옮길 때(forced narrative)는 " " 로 묶고, 대사와 한 자막에 섞지 않는다 |
| 두 사람 대사 | 한 자막에 두 사람이 말하면 줄마다 `- ` (하이픈 + 띄어쓰기)를 붙이고, 한 줄에 한 사람만 쓴다 |
| 숫자 · 단위 | 숫자는 글자나 숫자 어느 쪽도 된다. 시각은 군대 장면만 24시간제로 쓴다. 돈은 원으로 바꾸지 않고, 단위는 미터법으로 쓴다 |
| 띄어쓰기 | 지침이 국립국어원 규범(korean.go.kr)을 따르라고 한다 |

**자동으로 맞추는 곳:** `shared/srt-ko.mjs` 가 16자 · 두 줄 · 줄 끝 마침표 · 쉼표 제거 · `…` · `?!` · 피라미드 줄 나누기를 처리하고, 두 줄을 넘으면 자막을 나눈다. 읽기 속도는 경고만 한다.
- qna: `npm run motion-srt -- <편>` 이 이 모듈을 쓴다 (2026-11-01 부터). 7편 군대편까지 올린 `ko.srt` 는 예전 방식(한 줄에 최대 35자) 그대로다.
- 다른 채널(lab · shortube · funtube)에서 srt 를 만들 때도 이 모듈의 `splitKo()` 를 쓴다.
- **읽기 속도 경고:** 모답맨 · 내모남불은 음성을 1.2~1.25배로 빠르게 재생해서 초당 12자를 자주 넘는다. 자막 길이는 음성에 맞춰야 하니 늘리지 않는다. 대신 대본을 쓸 때 한 줄을 짧게 쓰고(15~20자 규칙), 경고가 많이 나오는 줄은 대본에서 줄인다.
- **화면에 박힌 자막**(영상 속 캡션 디자인)은 줄 끝 마침표 · 쉼표 없음 · `…` · `?!` 규칙만 따른다. 글자 크기와 줄 폭은 화면 디자인 규칙을 따른다.

## 5. HyperFrames — 지금은 쓰지 않는다

- HyperFrames 는 HeyGen 이 공개한 오픈소스다. HTML · CSS 와 시각 정보만으로 영상을 만들고, Claude Code 용 스킬을 함께 준다 (`npx skills add heygen-com/hyperframes`). Remotion 처럼 headless Chrome 과 FFmpeg 로 렌더한다.
- **기존 채널은 Remotion 을 계속 쓴다.** qna(모답맨 · 내모남불 · 모덕후 …)의 모션 엔진, 썸네일, 쇼츠, 인스타 판, shortube, funtube 가 모두 Remotion 컴포지션이다. 갈아타려면 엔진을 새로 짜야 하고, 그 이득도 확인된 적이 없다.
- 라이선스: Remotion 은 3명 이하 회사 · 개인은 무료다. 지금 이 저장소는 혼자 쓰므로 해당하지 않는다.
- 시험하려면 **새 프로젝트 하나**(새 시리즈나 새 채널)에서만, 사용자 허락을 받은 뒤 한다. 설치 전에 공식 저장소 `heygen-com/hyperframes` 의 라이선스와 최근 릴리스를 확인한다.

## 6. 효과음 — earshot

- 지금 쓰는 효과음은 `qna/video/scripts/sfx.mjs` 가 **코드로 합성한 것**이다 (pop · stamp · whoosh · buzz · ding …). 실제 음원을 쓰지 않는 규칙(shortube COMPLIANCE_GUIDE · 배경음악 규칙)과 맞다.
- `Leonxlnx/earshot` 도 효과음 201개를 코드로 렌더한다 (모델 · 네트워크를 쓰지 않음, Python 3.10 이상과 ffmpeg 필요). 영상 장면에 맞춰 효과음 자리를 잡아 주는 `earshot sfx` 명령도 있다. 우리 규칙과 맞는 방식이다.
- 개인이 만든 저장소다. 쓰기 전에 사용자에게 묻고, 코드와 라이선스를 읽은 다음 그 채널의 `.venv` 에 설치한다. 처음에는 한 편에서 `sfx.mjs` 와 나란히 들어 보고 비교해서 정한다.
- 효과음을 넣을 자리 규칙은 그대로다. 아이 눈높이 박자에는 효과음을 넣지 않는다 (qna/CLAUDE.md).
