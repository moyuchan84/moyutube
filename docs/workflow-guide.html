1-3. Remotion 영상 · 코드 합성 음악 (세 프로젝트 공통 방식)

  • 영상은 React 코드(Remotion)로 그린다. 같은 데이터면 같은 영상이 나와서 재현·수정이 쉽다. 프로젝트마다 node_modules 가 따로라 처음에 폴더에서 npm install. (버전: qna 4.0.525 · shortube 4.0.529 · funtube ^4.0.535)
  • 음악·효과음은 코드로 합성한다 (bgm*.mjs, sfx.mjs, beat.mjs). 외부 음원·유튜브 오디오 보관함 대신 쓰는 이유: Content ID 클레임 걱정이 없고, 같은 timeline.json 을 읽어 장면 전환·숫자가 박히는 순간에 소리를 정확히 맞출 수 있다. 설명란에는 [음악] 채널에서 직접 만든 배경음악.
  • 패턴: 장면 목록(timeline.json) → 영상 컴포넌트와 BGM 스크립트가 같은 파일을 읽음. 장면 길이를 바꾸면 BGM 도 다시 만들어야 맞는다 (npm run … 이 둘을 묶어 준다).
  • Claude 는 소리를 들을 수 없다. 음악·음성은 만든 뒤 "한 번 들어 봐 달라"고 말한다. 볼륨은 RMS 로 확인 (대략 −15 ~ −20 dBFS).

  • 장소가 답의 일부, 제삼의 인물이 답을 몸으로 보여 준다. 그림도 정적이지 않게 움직일 수 있는 구조로.
  • 6번 박자(아이 눈높이로 번역)에는 농담을 넣지 않는다. 가장 진지하게 가는 구간.
  • 분량은 8분 안팎 (3편 음성 약 321초에 배속 1.15). storyboard.html 과 기획서 콘티표의 시간으로 확인.
  • 대본을 고치면 기획서 .md 의 대본도 같이 고친다. 영상 대본이 원본이 된 뒤에는 script.json 기준.

특별 컷: "style":"triptych" + "triptych":[{art,name,label}] (세 칸 정리), "style":"end" + "end":{series,title,next} (끝 화면). 말하는 인물은 자동으로 까딱거리고, 가만 있어도 숨 쉬며 발밑 그림자가 생기고, 컷 내내 카메라가 천천히 밀고 들어간다 (src/Scene.tsx).

art.json — 그림 목록

  • cast: 가족이 아닌 사람의 생김새를 영어로 아주 구체적으로 적는다 (헤어 · 옷 · 표정 성격까지). 같은 사람이 매번 달라 보이지 않게 하는 핵심.
  • common: 쓸 공통 그림 id (아빠·아이 표정 등). items[]: 그 편 전용 그림 — id · kind · title · cuts(쓰는 컷) + 묘사.
  • 그림 종류 kind: char 전신 · cutin 가슴 위 · prop 소품 (이 셋은 초록 배경으로 뽑아 투명 처리) · bg 사람 없는 배경 · full 완성된 한 장짜리 장면(16:9). 확장: stage(주인공 자리를 비운 무대) · layer(배우를 가리는 앞쪽 물건) · talk(말하는 그림).
  • 말하는 그림 <그림>-b: 같은 자세에 입만 다른 두 번째 그림. 있으면 말하는 동안 번갈아 나와 입이 움직인다 (없어도 됨).
  • who + ref(기준 그림, 기준 그림 자신은 null)로 같은 인물을 이어 간다. inset: 0.025 는 그림 테두리 자르기, sky 는 장면 하늘색 지정.

3-6. 영상 코드 구조 (shortube/video)

video/ ├─ src/ │ ├─ Root.tsx ← 모든 컴포지션 등록 (RankingShort · MarketShort · KpopNumbers · DietNumbers · HeatShort · GtaShort · SuneungShort · UsShort …) │ ├─ theme.ts ← 폰트(Noto Sans KR) · 색 · FPS=30 · 1080×1920 │ ├─ components/Caption.tsx ← 하단 자막 (bottom 250, 줄 단위 · 강조 단어 노랑 형광펜) │ ├─ components/Kinetic.tsx · RankChart.tsx · Background.tsx │ ├─ market/effects.tsx ← Counter · Stamp · 흔들림 · clamp (여러 영상이 가져다 씀) │ └─ <주제>/ ← 한 영상 = 폴더 하나 │ ├─ timeline.json ← 장면(id·from·dur) · hits(숫자가 박히는 프레임) · risers(전환 직전 스웰) · bpm │ ├─ <Name>Short.tsx ← Sequence 로 장면을 이어 붙임 + BGM <Audio> │ ├─ scenes.tsx · fx.tsx ← 장면 컴포넌트 · 그 영상 전용 효과 │ └─ (데이터 json) ← kospi.json 등 ├─ scripts/bgm-*.mjs ← 코드 합성 BGM → public/bgm/*.wav ├─ scripts/market-data.mjs ← ../data/prices/*.csv → 영상용 JSON (이평 · RSI · 볼린저) └─ package.json ← "heat" · "gta" · "suneung" · "usmarket" · "market" 등: BGM 만들기 + 렌더를 한 줄로

새 영상을 추가하는 패턴 (예: UsShort)

  1. src/<주제>/timeline.json — 장면 길이(프레임, 30fps) · hits · risers. 합계가 total.
  2. fx.tsx(배경·전환·상단 띠) + scenes.tsx(장면별 컴포넌트 + Caption 줄) + <Name>Short.tsx(Sequence 조립).
  3. Root.tsx 에 <Composition id=… durationInFrames={TOTAL} …/> 추가, package.json 에 "<주제>": "node scripts/bgm-<주제>.mjs && remotion render …" 한 줄.
  4. npx tsc --noEmit 으로 타입 확인 → 스틸 점검 → npm run <주제>.

화면 규칙

  • 1080×1920. 자막은 하단 박스(bottom 250) — 본문 요소가 y≈1450 아래로 내려오면 겹친다. 줄바꿈이 어색하면 whiteSpace:"pre-line" 이나 wordBreak:"keep-all", 아니면 문장 수정.
  • 출처·기준일·고지는 마지막 장면 또는 상단 고정 띠(TopBand).
  • 브랜드(남색 + 노랑 선 + 분홍 점, Brand.tsx)는 첫 1초나 마지막 띠로만. 본문 배경까지 매번 남색으로 고정하지 않는다.
  • 쓸 수 있는 재료: 코드 생성(SVG 필터·입자·그라디언트·도형 패턴·카메라 이동·화면 나누기) / 라이선스 분명한 외부 자료(Natural Earth 지도 · Material Symbols · Tabler Icons · Noto Emoji · OFL 폰트 — 받으면 video/public/<종류>/LICENSE.md 에 출처·라이선스·날짜) / 사진·영상 클립은 쓰지 않는다.

3-7. 연출 카드 — 찍어낸 영상처럼 보이지 않게

브리프마다 7항목을 채운다: 팔레트 · 주 레이아웃 · 장면 전환 · 카메라 · 상징 오브젝트 · 타이포 · 템포. 규칙: 직전 2편과 7항목 중 4개 이상 달라야 하고, 같은 날 올리는 2편은 팔레트·주 레이아웃이 반드시 달라야 한다. 주제가 연출을 정한다 (더위 → 아지랑이·색 온도 / 시황 → 흔들림·긴박한 컷 / 수능 → 칠판·OMR / GTA → 노을 네온 고속도로 / 간밤 미국장 → 수심 눈금으로 낙하).

폭염 (HeatShort)주황→빨강→파랑으로 식음화면 반 나누기 + 지도아지랑이 녹임멈춤→식음

3-8. 배경음악 — 코드 합성

  • 외부 음원·오디오 보관함 대신 코드 합성이 기본. 설명란 [음악] 채널에서 직접 만든 배경음악.
  • 기존 스크립트(분위기별): bgm.mjs(밝고 잔잔) · bgm-tension.mjs(긴박·시황) · bgm-dance.mjs(밝은 댄스·K팝) · bgm-info.mjs(차분한 정보·의료, 리스크 구간 단조) · bgm-heat.mjs(더위→식음) · bgm-gta.mjs · bgm-suneung.mjs · bgm-usmarket.mjs(저음 드론 + 물방울). 새 주제는 비슷한 것을 복사해 진행·템포·화음만 바꾼다.
  • 구조: 마디 단위로 패드 코드 → 킥/물방울 같은 리듬 → timeline.json 의 risers(전환 직전 스웰) · hits(숫자 박히는 순간 킥/벨) → 끝 2초 페이드 → 정규화(tanh) → 16bit WAV. 마지막에 RMS dBFS 를 출력해 볼륨 점검 (대략 −15~−20, 영상 쪽 <Audio volume=0.75>).
  • 분위기 전환 아이디어: 특정 프레임(calmFrom·coolFrom) 이후 단조→장조, 킥 제거 — 이야기의 "식는 순간"을 소리로.

3-9. 시황 · 차트 주제를 만들 때 (가장 위험한 영역)

고정 문구와 금지

"투자 권유 아님 · 투자 판단과 책임은 본인" 고정. "사라/팔아라/바닥이다", 목표가, 유료 리딩 뉘앙스 금지. 한국 증시 월요일 전망 같은 예측도 쓰지 않는다. 방향 의견은 증권사·운용사 이름 + 보도 요지로 신중론/반등론을 같은 비중으로 (원문 직접 인용이 아니면 따옴표를 쓰지 않고 "보도 요지"로 표기).

  • 종가 기준·기준일을 화면에 상시 표기(TopBand). 미국장은 "미국 현지 종가".
  • 한국 차트 색: 상승 빨강 · 하락 파랑. 사용자가 "피로 물든"처럼 미국식 색으로 말해도 영상은 한국식 + 첫 장면에서 한 줄로 짚기.
  • 수치 검증 요령: 지수 종가를 (전날 종가 × 등락률)로 역산해 보도와 맞추면 1건 보도도 신뢰도가 올라간다. 일봉 기술 분석은 stockstealer 규칙(200일선 국면 · 이평 정배열 · RSI14 · 볼린저 · 지지·저항 피벗)을 같은 기준으로 세 차트에 적용 → "과매도 ✓ / 추세 ✗" 같은 판정 요약이 부가가치.
  • 못 찾은 값(예: 금요일 마감 금리)은 빈칸으로 두고 "확인하지 못해 싣지 않았습니다"라고 화면에 적는 편이 틀린 숫자보다 낫다.
  • 의료 주제: 효과와 같은 비중으로 부작용·중단 후 요요·규제, "전문의약품 · 의사 처방 필요 · 의학적 조언 아님" 상시 표기. 연예: 그룹 단위 공개 사실만, 미성년 개인 정보 금지.

4-4. 제작 순서

  1. 대본 쓰기 사람·Claudecontent/episodes.json 에 새 키(id)로 title · voices · lines 추가. 노래면 content/song.json. 하이브리드 콩트라면 줄마다 cam · face · act 까지 적는다(4-3).
  2. 표정 시트 준비 생성은 유료(하이브리드만) 캐릭터 묘사를 content/faces.json 의 characters 에 추가 → node scripts/facegen.mjs --list 로 프롬프트 확인(무료) → 요청이 있을 때만 facegen <이름>. 이미 있는 시트면 --process-only. 이 단계가 끝나야 public/faces/<이름>_1..6.png 가 생긴다.
  3. 컴포넌트 연결2D 형식은 기존 컴포넌트(Chat·Facts …)를 쓰면 되고, 새 형식이면 src/Root.tsx 의 EPISODES 배열에 {id, component} 추가 (EpisodeId 는 episodes.json 키에서 자동). 3D 콩트는 Carpool.tsx 를 복사해 EP · WHO · X(좌석 위치) · LOOK(옷·머리색) · CAMS 를 바꾼다.
  4. 음성 + 효과음 키가 있으면 유료npm run tts (특정 편만: node scripts/tts.mjs carpool). 효과음 14종은 이때 코드로 합성된다. 먼저 TTS_DRY=1 npm run tts 로 길이만 추정해 레이아웃을 확인하고(무료), 마음에 들면 키로 생성.
  5. 미리보기npm run studio → 샷·표정·연기·타이밍 확인. 대사만 고쳤다면 tts 를 다시 (바뀐 줄만 생성). 연기·카메라만 고쳤다면 음성은 그대로 두고 studio 로 확인.
  6. 렌더 무료npm run render (전부) 또는 node scripts/render.mjs carpool → out/<id>.mp4. 노래는 먼저 npm run beat. 3D 는 느리니 한 편씩.
  7. 타입 점검npm run typecheck.

scripts/render.mjs 의 기본 목록(all)은 chat skit facts balance fight ride ride3d ride3dface carpool 입니다. 새 형식을 추가하면 이 배열에도 넣어야 "전부 렌더"에 포함됩니다.

  • 모델 기본 gemini-2.5-flash-preview-tts (환경변수 GEMINI_TTS_MODEL 로 변경). 출력 24kHz 16bit 모노 PCM → WAV. 앞뒤 무음 자동 제거(0.05초만 남김).
  • 캐시: [모델|보이스|style|say] md5 가 같고 파일이 있으면 다시 생성하지 않는다 → 대사 하나만 고치면 그 줄만 과금. 429/5xx 는 15초씩 늘려 최대 6번 재시도.
  • 키 순서: 환경변수 GEMINI_API_KEY/GOOGLE_API_KEY → 루트 .env. 키가 없으면 음성 없이 글자 수 × 0.13초로 길이만 추정해 타이밍을 만든다 (레이아웃 점검용, 무료). TTS_DRY=1 로 일부러 키를 무시할 수 있다.
  • 효과음 14종은 저작권 걱정 없이 코드로 합성해 public/sfx/ 에 만든다: 기본 pop tick ding boom crinkle whoosh punch powerup + 콩트용 사운드 디자인(차 안) door(문) · blinker(깜빡이) · chime(내비 안내음) · heart(심장 소리 4박) · away(멀어지는 소리) · engine(엔진 저음, 반복 재생용). 새 효과음은 synth("이름", 길이초, (t,p)=>…) 한 줄 추가 후 tts 를 한 번 돌리면 생성된다(키 없어도 됨).
  • 하이브리드 콩트에서는 목소리마다 역할에 맞는 보이스 + 영어 톤(예: 선배 "scolding loudly, annoyed older boss", 후배 "flat deadpan, very tired", 내비 "robotic car navigation voice, polite and flat")을 줘서 연기와 어울리게 한다. 한 편에서 보이스가 겹치지 않게 voices 를 정한다.

4-7. 노래 영상 (beat.mjs · song.json)

  • song.json = title · lead · sections[]. 섹션: name · style(intro/verse/chorus/bridge/end) · bpm · energy(0~3) · lines[{who,text,beats}]. bpm: 0 이면 음악 없는 정적 구간(lines[].seconds 사용).
  • node scripts/beat.mjs (npm run beat) 가 이 구조대로 킥·스네어 등 비트를 코드로 합성해 public/bgm/ride.wav 로 저장 (고정 시드 잡음 → 매번 같은 소리, API 없음, 무료).
  • 영상 쪽 src/songTimeline.ts 가 같은 계산으로 가사 타이밍을 만들고, 풍경 이동 속도는 bpm × 7 px/초(정적 구간은 멈춤). beat.mjs 와 songTimeline.ts 의 계산이 어긋나면 소리와 가사가 어긋난다 — 한쪽을 고치면 다른 쪽도 같이.
  • 가사는 beats 로 길이를 정하므로, 박자 수만 바꿔 가사를 늘이고 줄인다.

4-8. 얼굴 표정 시트 — 하이브리드의 AI 쪽 (facegen.mjs)

3D 노래(ride3dface)와 3D 콩트(carpool)가 같은 표정 시트(public/faces/선배_1..6.png, 후배_1..6.png)를 쓴다. 캐릭터가 늘면 faces.json 의 characters 에 묘사를 추가해 시트를 새로 만든다. 표정 번호 의미는 4-3 의 표.

node scripts/facegen.mjs --list                  # 프롬프트만 출력 (무료)
node scripts/facegen.mjs 선배 후배                # Gemini 로 6칸 표정 시트 생성 (유료)
node scripts/facegen.mjs --process-only          # 이미 받은 원본(art/faces/raw_<이름>.png)만 다시 자르기 (무료)
node scripts/facegen.mjs --placeholder           # 임시 시트로 자르기만 — 파이프라인 점검 (무료)
node scripts/facegen.mjs 선배 --force            # 원본이 있어도 다시 생성 (유료)
  • content/faces.json = 화풍(한국 웹툰 개그체 "grotesque-cute") · 작업 지시 · 캐릭터별 묘사 · 6표정 · 레이아웃. 얼굴 이목구비만 초록(#00FF00) 배경에 3×2 격자로 그리게 한다 (머리 윤곽·머리카락·몸 없음 — 3D 머리에 투영하는 데칼).
  • 처리: 초록 키잉 → 가장 넓은 빈 틈 n개를 칸 경계로 → 6칸으로 잘라 public/faces/<이름>_1..6.png (투명 PNG). Gemini 가 오른쪽 아래에 넣는 작은 별 로고는 지운다.
  • 429 면 예비 키(GEMINI_API_KEY2)로 바꿔 재시도, 이미지 모델은 키로 쓸 수 있는 것 중 최신을 자동 선택(GEMINI_IMAGE_MODEL 로 고정 가능).
  • 표정 파일이 모자라면 원본(raw_*.png · _v1 · _v2-pale 버전들)을 art/faces 에 보관해 두고 --process-only 로 다듬기만 반복.
